# Поиск и загрузки Яндекс Музыки

Раздел «Поиск» добавляет в mustplay поиск треков по каталогу Яндекс Музыки и загрузку
аудиофайлов в локальную папку. Функциональность портирована из
[yandex-music-downloader](https://github.com/llistochek/yandex-music-downloader) на TypeScript
и выполняется целиком в Main-процессе: Python и новые npm-зависимости не добавляются,
стек остаётся единым (Electron + React + node:sqlite).

Загруженные файлы воспроизводятся обычным импортом папки в библиотеку. Потоковое
воспроизведение из Яндекс Музыки в этом выпуске не реализуется.

## Правовой и этический контекст

- Инструмент предназначен для личного использования владельцем действующей подписки
  Яндекс Музыки. Поиск и загрузка выполняются только с токеном, который пользователь
  вводит самостоятельно, и от его имени.
- Пользователь несёт ответственность за соблюдение условий использования Яндекс Музыки
  и применимого законодательства. Приложение не обходит платный доступ и не предназначено
  для распространения загруженных файлов.
- `PROJECT_SPEC.md` §2.2 относил «обход DRM или скачивание защищённых аудиопотоков» к
  направлениям, не реализуемым к первой защите (0.1), сохраняя их в долгосрочной концепции.
  Раздел «Поиск» — это направленная пользователем работа выпуска 0.9.0, которая развивает
  это направление в рамках личного использования по собственной подписке.
- Транспортное шифрование `encraw` (AES-256-CTR) расшифровывается ключом, который отдаёт
  официальный эндпоинт `file-info` для авторизованного пользователя. Это транспортная
  обфускация потока, а не взлом DRM: ключ доступен официальному клиенту с тем же токеном.
  Ключ принимается в hex или base64 (ровно 32 байта); если ключ непригоден, загрузка
  повторяется транспортом `raw`, который отдаёт тот же трек прямым потоком без ключа
  (как в консольном yandex-music-downloader и веб-клиенте). Ответ `file-info` читается
  и как `urls`, и как одиночный `url`.

## Архитектура

Границы соответствуют `AGENTS.md`: файлы, диалоги, хранилище, сеть и криптография
принадлежат Main; Renderer работает через типизированный API Preload и не имеет доступа к
Node.js, локальным путям или произвольным каналам IPC.

Модули Main:

- `yandex-api.ts` — клиент API Яндекс Музыки (поиск, `track`, `file-info`, lyrics, cover,
  открытие потока загрузки), подпись запросов `fileInfoSign`/`lyricsSign` (HMAC-SHA256),
  расшифровка `encraw`, тип `YandexError`. Не зависит от Electron.
  Контракт ответов: `/tracks/{id}` отдаёт массив треков внутри конверта
  `{ invocationInfo, result }`, а `getJson` разворачивает только объектный `result`,
  поэтому массив конверта обрабатывает `trackEntry`. Поток загрузки с CDN открывается
  с теми же заголовками сессии, что и запросы API (`X-Yandex-Music-Client`, `User-Agent`,
  `Authorization`) — как в консольном yandex-music-downloader.
- `yandex-downloads.ts` — менеджер загрузок `YandexDownloads`: очередь, прогресс, отмена,
  sanitization имён, временные файлы, теги. Не зависит от Electron; API внедряется через
  фабрику `createApi` для тестируемости.
- `yandex-tags.ts` — контейнеры по кодеку и запись тегов (включая обложку и текст).
- `yandex-cover.ts` — `YandexCoverProxy`: отдаёт обложки результатов поиска через протокол
  `mustplay://app/yandex-cover/<trackId>` с кэшированием и проверкой MIME.
- `yandex-service.ts` — регистрация IPC-обработчиков, диалог выбора папки, открытие
  страницы получения токена. Единственный модуль, знающий об Electron (токен читается и
  пишется через общий `yandex-token.ts`).

Renderer: `search.tsx` (раздел «Поиск», карточка настроек, результаты, панель загрузок),
подключён в `app.tsx` как пункт меню «Поиск». Общие DTO и каналы — в `src/shared/contracts.ts`.

## Безопасность

- Каждый новый IPC-обработчик первым делом вызывает `senderWindow(event)`: проверяются
  отправитель (`event.sender === window.webContents`), кадр (`senderFrame === mainFrame`) и
  URL кадра (`entryUrl`). При нарушении возвращается `IPC sender denied`. Проверяется также
  число и тип аргументов; произвольные пути от Renderer не принимаются.
- Каналы только именованные (`yandex:*`), добавлены в общий контракт и Preload. Сохранены
  sandbox, context isolation, CSP и запрет Node.js в Renderer.
- Токен хранится в `yandex_settings` зашифрованным через `safeStorage` (DPAPI на Windows).
  Если шифрование недоступно, токен сохраняется в открытом виде локально в профиле — это
  документированное ограничение; флаг `token_encrypted` отражает режим. Токен не покидает
  Main и не передаётся в Renderer (наружу отдаётся только `hasToken`).
- Тот же токен использует вкладка «Импорт»: `src/main/yandex-token.ts` — единственное место
  чтения и записи, поэтому токен, сохранённый в поиске, сразу работает в импорте и наоборот.
- Обложки проходят ограниченную проверку `artworkMime` (сигнатура, статичность, лимит
  размера) перед отдачей; идентификатор трека в URL проверяется шаблоном `^\d{1,20}$`.
- Имена файлов и папок очищаются от недопустимых символов и управляющих кодов, обрезаются
  до 180 символов; коллизии разрешаются добавлением ID трека. Запись идёт во временные
  файлы `.mustplay-<id>.raw.tmp` / `.mustplay-<id>.tmp` с последующим переименованием.
- При отмене дескриптор файла закрывается до удаления временного файла (иначе на Windows
  файл с открытым дескриптором не удаляется). Размер трека ограничен 512 МБ, число заданий
  в истории — 200.

## Хранилище

Миграция схемы 15 добавляет таблицу `yandex_settings` (одна строка, `id CHECK = 1`):
`token BLOB`, `token_encrypted`, `quality` (`lq`/`nq`/`lossless`), `lyrics`
(`none`/`text`/`lrc`), `embed_cover`, `folder`. Значения по умолчанию: `nq`, `lrc`,
включение обложки, пустые токен и папка.

После объединения с линией импорта (0.11.0) миграции именованы и записываются в
`schema_migrations`. База 0.9.0 имела `yandex_settings` под номером 13, а линия импорта —
`isrc_cache` и `pipeline_jobs` под 12 и 13; при обновлении применяется только недостающее,
поэтому ни одна линия не повторяет чужую миграцию.

## Поток загрузки

Статусы: `queued → downloading → tagging → complete` (либо `error`/`cancelled`).
Конвейер: `track` → `file-info` → выбор контейнера по кодеку → sanitизированный путь →
потоковая загрузка во временный файл → расшифровка `encraw` при наличии ключа → получение
текста/обложки → запись тегов → атомарное переименование → sidecar `.lrc` при формате LRC.
Прогресс и статусы транслируются в Renderer событием `yandex:downloads`.

## IPC-контракт

Каналы: `yandex:get-settings`, `yandex:set-token`, `yandex:set-quality`, `yandex:set-lyrics`,
`yandex:set-embed-cover`, `yandex:choose-folder`, `yandex:open-token-page`, `yandex:search`,
`yandex:download`, `yandex:cancel-download`, `yandex:get-downloads`, `yandex:downloads`
(событие). DTO: `YandexSettings`, `YandexTrack`, `YandexSearchResult`, `YandexDownload`.
Методы Preload перечислены в `MustplayApi` (`src/shared/contracts.ts`).

## Тестирование

- `tests/yandex-api.test.ts`, `yandex-tags.test.ts`, `yandex-cover.test.ts`,
  `yandex-downloads.test.ts` — модульные тесты клиента, тегов, прокси обложек и менеджера
  загрузок (включая расшифровку, отмену в полёте и очистку временных файлов, неподдерживаемый
  кодек). Загрузки тестируются на синтетических фикстурах через внедрённую фабрику API.
- `tests/electron-smoke.mjs` — контракт API `window.mustplay` расширен новыми методами;
  тест отказа IPC для неавторизованного окна покрывает новые обработчики. Фаза `search-ui`
  (вызывается из `tests/desktop.mjs`) проверяет рендер раздела «Поиск», пустые состояния,
  правовой дисклеймер и сохранение настроек качества/текста/обложки по IPC. Legacy-тесты
  схемы обновлены до версии 15 (`yandex_settings`).
- `pnpm build`, `pnpm test` и desktop-проверка выполняются перед передачей работы.

Примечание о среде: в текущем окружении Node.js доступен только как Electron-as-Node
(`ELECTRON_RUN_AS_NODE=1`). Обёртка `pnpm test:desktop` (`node --test`) в этом режиме
неработоспособна: ESM-импорт `electron` возвращает объект API вместо пути к исполняемому
файлу, а дочерний процесс наследует `ELECTRON_RUN_AS_NODE`. Поэтому фазы `import` и
`restart` смоук-теста запускались напрямую под реальным Electron без изменения тестового
кода; обе фазы прошли (загрузка приложения, контракт API, отказ IPC, импорт,
воспроизведение, обложки, сохранение библиотеки между перезапусками).

## Ограничения

- Потоковое воспроизведение из Яндекс Музыки не поддерживается; загруженные файлы
  воспроизводятся через импорт папки в библиотеку.
- Поиск и загрузка требуют действующего токена; загрузка также требует выбранной папки.
- При недоступности DPAPI/keyring токен хранится в открытом виде в профиле.
- Качество `lossless` доступно только для треков, отдаваемых в FLAC; неподдерживаемый кодек
  завершает задание ошибкой.
