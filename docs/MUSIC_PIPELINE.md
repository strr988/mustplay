# Импорт музыки (0.9.0)

Пайплайн собирает локальную копию плейлиста из бесплатных источников и
подтверждает каждый файл отпечатком Chromaprint через AcoustID. Это не
замена плееру: импортированные файлы лежат отдельно, а существующая
медиатека, волна, плейлисты и настройки продолжают работать как раньше.

## Поток

1. Пользователь вставляет ссылку на плейлист Deezer или Spotify либо открывает
   YT Music в веб-сессии и выбирает плейлист там.
2. Провайдер отдаёт список треков: название, исполнитель, альбом, длительность
   и, если он его знает, ISRC.
3. Если ISRC нет (публичная страница Spotify, YT Music), он ищется по
   метаданным: сначала Deezer, затем MusicBrainz. Совпадение проверяется по
   названию, исполнителю и длительности.
4. Если источник уже знает точную запись (YT Music `videoId`), ссылка на аудио
   берётся напрямую и поиск yt-dlp не выполняется.
5. Иначе yt-dlp ищет 5 кандидатов и выбирает лучшего по совпадению текста и
   длительности.
6. Аудио скачивается как `bestaudio/best` без перекодирования.
7. `fpcalc` считает отпечаток, AcoustID возвращает записи и их ISRC.
8. Файл остаётся, только если ISRC совпал или уверенность AcoustID высокая.
9. Подтверждённый файл запоминается в SQLite (`isrc_cache`, `fingerprint_cache`),
   чтобы повторный импорт не скачивал его снова.

Отклонённые загрузки удаляются. В разделе «Импорт» видно, какой трек
обрабатывается сейчас, сколько подтверждено, отброшено, завершилось ошибкой и
осталось, плюс прогресс-бар и лог по каждому треку.

## Провайдеры

| Платформа | Статус | Доступ | ISRC |
| --- | --- | --- | --- |
| Deezer | работает | публичный API | да |
| Spotify | работает | публичная страница без аккаунта; Web API опционально для Premium | нет на странице, ищется по метаданным |
| YT Music | работает | веб-сессия пользователя (`WebContentsView`) | нет, ищется по метаданным |
| Apple Music | заглушка | нужен платный Apple Developer | — |
| Яндекс Музыка | заглушка | токен | — |
| ВК Музыка | заглушка | токен | — |
| SoundCloud | заглушка | ключ приложения | — |

Apple Music исключён из плана: проект остаётся полностью бесплатным.

Публичная страница Spotify (`open.spotify.com/embed/playlist/…`) отдаёт до
100 треков, название, исполнителя и длительность, но не ISRC. Это путь по
умолчанию. Если в настройках подключён Spotify Web API, используется он.

## Веб-сессия YT Music

Кнопка «Открыть YT Music» показывает настоящую страницу сервиса в
`WebContentsView`:

- отдельная партиция `persist:mustplay-sources`, cookies не смешиваются с
  приложением;
- без preload, с `sandbox` и `contextIsolation`, без доступа к `window.mustplay`;
- разрешения и всплывающие окна запрещены, навигация ограничена доменами
  YouTube и Google, загрузки блокируются;
- пароль вводится только на странице сервиса, приложение его не видит;
- «Выйти и удалить данные» очищает cookies, хранилище и кэш партиции.

При импорте приложение читает `ytInitialData` страницы плейлиста и
продолжения через внутренний `/youtubei/v1/browse`, используя cookies текущей
сессии. Каждый трек получает точный `videoId`, поэтому скачивается прямая
ссылка `https://www.youtube.com/watch?v=…`.

Ограничения режима: это неофициальный доступ, сервис может показать капчу или
ограничить аккаунт; разметка и внутренние эндпоинты могут измениться; ISRC в
вебе не отдаётся, поэтому резолв через Deezer/MusicBrainz и проверка AcoustID
остаются обязательными.

## Настройка Spotify (необязательно)

Публичная страница работает без аккаунта. Web API нужен только тем, у кого
есть Spotify Premium: с 2025 года новые интеграции требуют Premium.

1. Создайте приложение на <https://developer.spotify.com/dashboard>.
2. Добавьте Redirect URI `http://127.0.0.1:8888/callback`.
3. В User Management добавьте свой аккаунт (приложение в development mode).
4. Вставьте Client ID в настройках импорта и нажмите «Подключить Spotify».
5. Браузер откроется сам; после разрешения доступа mustplay поймает код на
   локальном loopback-порту 8888. Порт должен быть свободен.

Токен доступа живёт в памяти и не переживает перезапуск: после старта
приложения Spotify нужно подключить снова. Это осознанное ограничение 0.9.0,
чтобы не хранить refresh-токены на диске.

## Инструменты

Кнопка «Установить инструменты» скачивает официальные релизы в
`<userData>/tools`:

- `yt-dlp` — GitHub releases, `latest/download`;
- `fpcalc` — Chromaprint releases, последний релиз через GitHub API;
  архив распаковывается системным `tar` (есть в Windows 10+ и macOS/Linux).

Если установка не удалась, подсказка показывает причину. Можно поставить
`yt-dlp` и `fpcalc` вручную в `PATH` — они будут найдены.

## Лимиты

- AcoustID: 3 запроса в секунду, один общий лимитер на все воркеры.
- MusicBrainz: 1 запрос в секунду, обязательный User-Agent не требуется для
  публичного поиска по ISRC, но лимит соблюдается.
- Deezer: 5 запросов в секунду.
- Spotify: 5 запросов в секунду.
- Загрузок параллельно: 1–5, по умолчанию 3.

SQLite-записи выполняются транзакциями, поэтому прерывание импорта не
оставляет частичных записей кэша.

## Где лежат данные

- Настройки: `<userData>/pipeline-settings.json`.
- Инструменты: `<userData>/tools`.
- Аудио: папка, выбранная в настройках импорта.
- Кэш ISRC и отпечатков: таблицы `isrc_cache` и `fingerprint_cache` в
  `library-player-experience.sqlite3` (схема 13).
- Сессия YT Music: партиция `persist:mustplay-sources` в профиле Electron.

## Ошибки и подсказки

- Ключ AcoustID проверяется сервисом. Если он отклонён (`invalid API key`),
  импорт останавливается сразу: повторять загрузку для каждого трека
  бессмысленно. Бесплатный ключ выдаётся на
  <https://acoustid.org/new-application>.
- Если yt-dlp не может открыть YouTube (SSL, сброс соединения, таймаут), в
  логе остаётся исходный текст ошибки и подсказка проверить VPN, прокси или
  блокировку. Повторные попытки поиска делаются автоматически.
- Неподтверждённые загрузки удаляются, поэтому после неудачного прогона в
  папке аудио не остаётся мусора.
- AcoustID принимает список `meta` только через пробел: сервис разбирает
  значение по пробельным символам. Литеральный `+` (как в примерах с GET,
  где он означает пробел) не вызывает ошибку, но и не возвращает записи —
  поэтому запрос отправляет `recordings isrcs` через форму, которая кодирует
  пробел как `+`.

## Ограничения 0.9.0

- Публичная страница Spotify отдаёт не больше 100 треков и не отдаёт ISRC.
- YT Music читается через веб-сессию: возможны капча и ограничения аккаунта.
- Нет cookies для YouTube-поиска: закрытые/возрастные видео могут не скачаться.
- Нет перекодирования в mp3/flac: сохраняется исходный контейнер yt-dlp.
- Нет refresh-токена Spotify и фонового повтора неудачных треков.
- Заглушки провайдеров отвечают понятной ошибкой, а не пустым экраном.

## Проверка

```powershell
pnpm typecheck
pnpm build
pnpm test
pnpm test:desktop
```

Юнит-тесты покрывают парсинг Deezer, публичной страницы Spotify, YT Music
(`ytInitialData`, продолжения, конфиг), выбор ISRC по метаданным, матчинг и
сухой прогон пайплайна с прямым источником. Живой прогон требует ключа
AcoustID, установленных `yt-dlp`/`fpcalc` и ссылок на плейлисты. Для YT Music
нужно войти в свой аккаунт в открытом окне сервиса.
