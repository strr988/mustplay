# Импорт музыки (0.10.0)

Пайплайн собирает локальную копию плейлиста из бесплатных источников и
подтверждает каждый файл отпечатком Chromaprint через AcoustID. Готовые треки
сразу становятся плейлистом в библиотеке: название, исполнитель, альбом,
длительность и жанры берутся из источника, а не из имени файла. Это не замена
плееру: существующая медиатека, волна, плейлисты и настройки продолжают
работать как раньше.

## Поток

1. Пользователь вставляет ссылку на плейлист Deezer или Spotify либо открывает
   Яндекс Музыку, ВК Музыку, SoundCloud или YT Music в веб-сессии и выбирает
   плейлист там.
2. Провайдер отдаёт список треков: название, исполнитель, альбом, длительность
   и, если он его знает, ISRC.
3. Если ISRC нет (публичная страница Spotify, YT Music, ВК, SoundCloud), он
   ищется по метаданным: сначала Deezer, затем MusicBrainz. Совпадение
   проверяется по названию, исполнителю и длительности.
4. Если источник уже знает точную запись (YT Music `videoId`, ссылка
   SoundCloud/ВК), поиск yt-dlp не выполняется: скачивается прямая ссылка.
5. Иначе yt-dlp ищет 5 кандидатов. Если известна длительность трека,
   загрузки, отличающиеся больше чем на `max(20 с, 15%)`, отбрасываются:
   обрезки и живые версии часто называются так же. Из оставшихся выбирается
   лучший по совпадению текста и длительности.
6. Аудио скачивается в `m4a` (по умолчанию, играет на телефоне и в машине) или
   в исходном контейнере (`webm/opus`) — выбор в разделе «Импорт».
7. `fpcalc` считает отпечаток, AcoustID возвращает записи и их ISRC.
8. Файл остаётся, только если ISRC совпал или уверенность AcoustID высокая.
9. Подтверждённый файл запоминается в SQLite (`isrc_cache`, `fingerprint_cache`),
   чтобы повторный импорт не скачивал его снова. Повторно найденный трек
   помечается «Уже в библиотеке».
10. После завершения файлы сканируются, метаданные источника записываются в
    библиотеку, а из подтверждённых треков создаётся плейлист с названием
    исходного. На экране результата есть «Слушать» и «Открыть плейлист».

Отклонённые загрузки удаляются. В разделе «Импорт» видно, какой трек
обрабатывается сейчас, сколько подтверждено, не подтверждено, завершилось
ошибкой и осталось, плюс прогресс-бар и список треков. У отброшенного трека
есть «Другая версия» и «Пропустить», у ошибки — «Повторить». Технические
подробности (ISRC, уверенность, путь) спрятаны в раскрывающемся блоке.

## Нулевая настройка

- Папка по умолчанию — `%USERPROFILE%\Music\mustplay`; создаётся автоматически.
- `yt-dlp` и `fpcalc` ставятся сами при первом импорте. При ошибке установки
  кнопка «Повторить» запускает попытку снова.
- Встроенный ключ AcoustID приложения работает без регистрации. Свой ключ
  можно указать в «Дополнительно»; он нужен только для личных лимитов.
- Число параллельных загрузок по умолчанию 3; папка, ключ, инструменты и
  Spotify Web API находятся в «Дополнительно».
- История заданий хранится в SQLite и переживает перезапуск.

## Провайдеры

| Платформа | Статус | Доступ | ISRC |
| --- | --- | --- | --- |
| Deezer | работает | публичный API | да |
| Spotify | работает | публичная страница без аккаунта; Web API опционально для Premium | нет на странице, ищется по метаданным |
| YT Music | работает, если доступен YouTube | веб-сессия пользователя (`WebContentsView`) | нет, ищется по метаданным |
| Яндекс Музыка | токен принимается в «Дополнительно»; чтение через API ещё не подключено | нужен новый API `api.music.yandex.net` и OAuth-токен аккаунта | редко, ищется по метаданным |
| ВК Музыка | не работает для аудио | у yt-dlp нет экстрактора VK-аудио; нужен собственный резолвер прямых ссылок | нет, ищется по метаданным |
| SoundCloud | чтение плейлистов работает; треки с DRM не скачиваются | ссылка на публичный плейлист (yt-dlp) или веб-сессия | нет, ищется по метаданным |
| Apple Music | не поддерживается | нужен платный аккаунт | — |

Apple Music исключён из плана: проект остаётся полностью бесплатным.

## Политика метаданных

Это требование, а не пожелание: «Волна» выбирает треки по признакам, и
неполные метаданные ломают подбор. Поэтому каждый провайдер обязан вернуть
**полный набор** — иначе импорт считается незавершённым:

| Поле | Где используется |
| --- | --- |
| название, исполнитель, все исполнители | карточка, поиск, «Волна» |
| альбом, год, номер трека, лейбл | группировка, «Волна», теги файла |
| жанры | «Волна», фильтры, теги файла |
| длительность | сверка отпечатка, совпадение с источником |
| ISRC | точный резолв в Deezer/Spotify |
| обложка | карточка и плеер (локальный файл, не горячая ссылка CDN) |
| лицензия и ссылка на источник | прозрачность и повторный импорт |
| текст трека | экран текста; качается отдельно, там где сервис его отдаёт |

Ничего из этого не выбрасывается молча: если сервис поле не отдал, это
фиксируется в задании импорта, а не подменяется догадкой.

То же правило действует для файла: после скачивания в `.m4a`/`.mp3`
прописываются название, исполнитель, альбом, жанр, год, номер трека и
обложка, чтобы библиотека оставалась читаемой вне приложения.

### Проверено вживую 16.11.2026

Сеть пользователя (Ростелеком, без VPN) блокирует не только сайты, но и CDN:

| Проверка | Результат |
| --- | --- |
| `www.youtube.com`, `googlevideo.com` | сброс соединения / таймаут, yt-dlp тоже не проходит |
| SoundCloud: чтение плейлиста | работает |
| SoundCloud: сегмент аудио | ~260 Б/с — скачивание практически невозможно |
| VK: `yt-dlp --list-extractors` | только `vk`, `vk:uservideos`, `vk:wallpost`; аудио нет |
| Яндекс: `handlers/playlist.jsx` | `301` на главную; этот адрес использует и yt-dlp |
| Яндекс: `api.music.yandex.net` | отвечает, но нужен токен |
| Deezer API / страница Spotify | читаются |

Поэтому при заблокированном YouTube не скачивается звук ни у одного источника:
Deezer и Spotify дают только метаданные и ISRC, а файл всё равно берётся с
YouTube. Рабочий обход — системный VPN в режиме TUN (например, Happ с VLESS):
он заворачивает трафик yt-dlp и веб-сессий без отдельной настройки прокси.

SoundCloud-плейлисты читаются по ссылке напрямую, без открытия сайта: это
работает, даже когда `soundcloud.com` блокируется, потому что метаданные
приходят с `api-v2.soundcloud.com`.

Публичная страница Spotify (`open.spotify.com/embed/playlist/…`) отдаёт до
100 треков, название, исполнителя и длительность, но не ISRC. Это путь по
умолчанию. Если в настройках подключён Spotify Web API, используется он.

Жанры берутся у Deezer для альбома (`/album/{id}` → `genres.data[].name`) и
кэшируются на время импорта; если Deezer их не знает, используются жанры
MusicBrainz (`inc=genres+tags`). Жанры пишутся в библиотеку, а не в теги файла:
скачанный webm/opus часто вообще без тегов.

## Веб-сессии сервисов

Кнопки «YT Music», «Яндекс Музыка», «ВК Музыка» и «SoundCloud» показывают
настоящую страницу сервиса в `WebContentsView`:

- отдельная партиция `persist:mustplay-sources`, cookies не смешиваются с
  приложением; один вход на все сервисы;
- без preload, с `sandbox` и `contextIsolation`, без доступа к `window.mustplay`;
- разрешения и всплывающие окна запрещены, навигация ограничена HTTPS-доменами
  выбранных сервисов, загрузки блокируются;
- пароль вводится только на странице сервиса, приложение его не видит;
- «Выйти и удалить данные» очищает cookies, хранилище и кэш партиции.

Чтение плейлиста зависит от сервиса:

- YT Music: `ytInitialData` и продолжения через внутренний
  `/youtubei/v1/browse`; каждый трек получает точный `videoId`.
- Яндекс Музыка: `handlers/playlist.jsx` больше не отдаёт JSON (`301` на
  главную), поэтому импорт ждёт перехода на `api.music.yandex.net` с токеном.
  Токен уже можно сохранить в «Дополнительно»: поле принимает OAuth-токен,
  держит его в Main и профиле приложения, а в интерфейсе показывает только
  отметку «Токен сохранён».
- SoundCloud: публичный плейлист читается по ссылке без входа (`yt-dlp`), а
  закрытые подборки — из веб-сессии с cookies. Сеты и альбомы читаются в
  полном режиме, потому что «плоский» список не содержит названий: до 100
  треков, зато с настоящими названиями, исполнителями и ссылками.
- ВК Музыка: чтение идёт через веб-сессию, но у yt-dlp нет экстрактора
  VK-аудио, поэтому скачивание пока не реализовано.

Ограничения режима: это неофициальный доступ, сервис может показать капчу или
ограничить аккаунт; разметка и внутренние эндпоинты могут измениться; ISRC в
вебе чаще всего не отдаётся, поэтому резолв через Deezer/MusicBrainz и проверка
AcoustID остаются обязательными.

## Настройка Spotify (необязательно)

Публичная страница работает без аккаунта. Web API нужен только тем, у кого
есть Spotify Premium: с 2025 года новые интеграции требуют Premium.

1. Создайте приложение на <https://developer.spotify.com/dashboard>.
2. Добавьте Redirect URI `http://127.0.0.1:8888/callback`.
3. В User Management добавьте свой аккаунт (приложение в development mode).
4. Вставьте Client ID в настройках импорта и нажмите «Подключить Spotify».
5. Браузер откроется сам; после разрешения доступа mustplay поймает код на
   локальном loopback-порту 8888. Порт должен быть свободен.

Токен доступа живёт в памяти и не переживает перезапуск: после старта
приложения Spotify нужно подключить снова. Это осознанное ограничение 0.10.0,
чтобы не хранить refresh-токены на диске.

## Инструменты

Инструменты ставятся автоматически при первом импорте или при первом чтении
плейлиста ВК/SoundCloud в `<userData>/tools`:

- `yt-dlp` — GitHub releases, `latest/download`;
- `fpcalc` — Chromaprint releases, последний релиз через GitHub API;
  архив распаковывается системным `tar` (есть в Windows 10+ и macOS/Linux).

В «Дополнительно» видно состояние и есть кнопка повторной установки. Если
установка не удалась, подсказка показывает причину. Можно поставить `yt-dlp` и
`fpcalc` вручную в `PATH` — они будут найдены.

## Лимиты

- AcoustID: 3 запроса в секунду, один общий лимитер на все воркеры.
- MusicBrainz: 1 запрос в секунду, обязательный User-Agent не требуется для
  публичного поиска по ISRC, но лимит соблюдается.
- Deezer: 5 запросов в секунду.
- Spotify: 5 запросов в секунду.
- Загрузок параллельно: 1–5, по умолчанию 3.

SQLite-записи выполняются транзакциями, поэтому прерывание импорта не
оставляет частичных записей кэша.

## Где лежат данные

- Настройки: `<userData>/pipeline-settings.json`.
- Инструменты: `<userData>/tools`.
- Аудио: `%USERPROFILE%\Music\mustplay` по умолчанию, можно сменить в
  «Дополнительно».
- Кэш ISRC и отпечатков: таблицы `isrc_cache` и `fingerprint_cache`, история
  заданий — `pipeline_jobs` в `library-player-experience.sqlite3`
  (схема 14).
- Плейлист импорта: обычные `playlists` и `playlist_items`, поэтому он сразу
  доступен в разделе «Плейлисты».
- Сессии сервисов: партиция `persist:mustplay-sources` в профиле Electron.

## Ошибки и подсказки

- Встроенный ключ AcoustID используется, пока пользователь не указал свой.
  Если ключ отклонён (`invalid API key`), импорт останавливается сразу:
  повторять загрузку для каждого трека бессмысленно. Бесплатный ключ выдаётся
  на <https://acoustid.org/new-application>.
- Если yt-dlp не может открыть YouTube (SSL, сброс соединения, таймаут), в
  логе остаётся исходный текст ошибки и подсказка проверить VPN, прокси или
  блокировку. Повторные попытки поиска делаются автоматически.
- Если источник отвечает `DRM protected` (типично для лейбловых треков
  SoundCloud), строка получает сообщение «Трек защищён DRM в источнике»:
  такая запись не скачивается ни при каком VPN, её нужно искать в другом
  источнике.
- Неподтверждённые загрузки удаляются, поэтому после неудачного прогона в
  папке аудио не остаётся мусора.
- Строка «Не удалось скачать» предлагает «Повторить», а «На YouTube нашлась
  другая версия…» — «Другую версию» или «Пропустить». Повтор идёт в том же
  задании и не создаёт новый плейлист.
- AcoustID принимает список `meta` только через пробел: сервис разбирает
  значение по пробельным символам. Литеральный `+` (как в примерах с GET,
  где он означает пробел) не вызывает ошибку, но и не возвращает записи —
  поэтому запрос отправляет `recordings isrcs` через форму, которая кодирует
  пробел как `+`.

## Ограничения 0.10.0

- Публичная страница Spotify отдаёт не больше 100 треков и не отдаёт ISRC.
- Веб-сессии неофициальные: возможны капча и ограничения аккаунта.
- Нет cookies для YouTube-поиска: закрытые/возрастные видео могут не скачаться.
- Нет перекодирования в mp3: выбор только `m4a` или исходный контейнер.
- Нет refresh-токена Spotify и фонового повтора неудачных треков: повтор
  запускается вручную на строке трека.
- Apple Music не поддерживается.

## Проверка

```powershell
pnpm typecheck
pnpm build
pnpm test
pnpm test:desktop
```

Юнит-тесты покрывают парсинг Deezer, публичной страницы Spotify, YT Music
(`ytInitialData`, продолжения, конфиг), Яндекс Музыки, плоского плейлиста
yt-dlp (ВК, SoundCloud), выбор формата и разбор пути загрузки, выбор ISRC по
метаданным, матчинг и сухой прогон пайплайна с прямым источником. Отдельный
тест проверяет, что завершённое задание становится плейлистом с метаданными и
жанрами источника, а история переживает переоткрытие базы. Живой прогон требует
установленных `yt-dlp`/`fpcalc` и ссылок на плейлисты. Для YT Music нужно войти
в свой аккаунт в открытом окне сервиса; публичный плейлист SoundCloud читается
по ссылке без входа.
